# 🚀 ตารางสรุปผลการเปรียบเทียบ (Comparison table)

| คุณลักษณะ                   | REST                                                                                              | GraphQL                                                                                |
| :-------------------------- | :------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------- |
| **`รูปแบบการเข้าถึง`**      | **`Multiple Endpoints`** แยกตาม Resource เช่น `/api/v1/students`, `/api/v1/courses`               | **`Single Endpoint`** เข้าผ่านช่องทางเดียวเสมอ เช่น `/graphql`                         |
| **`ขนาดข้อมูลที่ได้รับ`**   | **`Fixed Data Structure`** Server กำหนดมาอย่างไร Client ต้องรับทั้งหมด (เกิด Over/Under-fetching) | **`Flexible Data Selection`** Client เลือกฟิลด์ที่ต้องการได้เองตาม Schema              |
| **`การดึงข้อมูลสัมพันธ์`**  | ยิงหลายรอบ หรือทำ Custom Endpoint ต้องต่อหลาย URL หรือทำแบบ `/student/:id/full`                   | ยิงรอบเดียวจบ (Nested Query) ระบุความสัมพันธ์สืบลึกได้ใน Request เดียว                 |
| **`การจัดการประเภทข้อมูล`** | ไม่มี Built-in Type System ในตัว (ส่งเป็น JSON กว้างๆ)                                            | มี Strongly Typed Schema ชัดเจน (ระบุ ID!, String!, Int! ล่วงหน้า)                     |
| **`การทำ Caching`**         | ทำได้ง่ายมาก ใช้กลไก HTTP Cache มาตรฐาน (กุมความสัมพันธ์ด้วย URL)                                 | ทำยากกว่า เนื่องจากใช้ POST ไปที่ URL เดียว ต้องพึ่งพา Client-side Cache (เช่น Apollo) |

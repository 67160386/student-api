# 🚀 ทบทวนคุณภาพของโค้ด (Code Quality Review)

---

## 📑 ข้อ 1: โค้ดใน index.js มีการตรวจสอบข้อมูลนำเข้า (validation) ก่อนประมวลผลหรือไม่

ในฟังก์ชันการทำงานส่วนของ **POST** และ **PUT**

- มีการตรวจสอบว่ามี `name` และ `major` มาใน `req.body` หรือไม่
- หากไม่มีหรือส่งมาไม่ครบ จะทำการ `return` และ
- ส่ง **Status Code: 400 Bad Request** พร้อมข้อความแจ้งเตือน

---

## 📑 ข้อ 2: ทุก route มีการตอบกลับด้วย Status Code ที่เหมาะสมกับผลลัพธ์หรือไม่

เหมาะสมถูกต้อง

| Status Code           | ประเภท       | คำอธิบายการนำไปใช้ในโค้ด                                                      |
| :-------------------- | :----------- | :---------------------------------------------------------------------------- |
| **`200 OK`**          | Success      | ดึงข้อมูลสำเร็จ (`GET`), แก้ไขข้อมูลสำเร็จ (`PUT`), ลบข้อมูลสำเร็จ (`DELETE`) |
| **`201 Created`**     | Success      | สร้างข้อมูลนักศึกษาใหม่ลงในระบบสำเร็จ (`POST`)                                |
| **`400 Bad Request`** | Client Error | ผู้ใช้ส่งข้อมูลมาไม่ครบถ้วนตามเงื่อนไขที่กำหนด (Validation Failed)            |
| **`404 Not Found`**   | Client Error | ไม่พบข้อมูลนักศึกษาในระบบ จาก `id` ที่ระบุเข้ามา                              |

---

## 📑 ข้อ 3: โครงสร้างโค้ดในไฟล์เดียวยังอ่านง่ายอยู่หรือไม่ หากมี route เพิ่มขึ้นอีก 10 เส้นทาง จะเกิดปัญหาใดตามมา

- **ถ้ามี 5 เส้นทาง:** ยังอ่านง่าย และไล่โค้ดได้รวดเร็ว เหมาะกับระบบขนาดเล็ก
- **ถ้าเพิ่มขึ้นอีก 10 เส้นทาง (หรือมากกว่านั้น):** จะทำให้โค้ดอ่านยากและอาจเกิดข้อผิดพลาดที่มากยิ่งขึ้น
